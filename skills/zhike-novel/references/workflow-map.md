# 工作流地图（调用关系 + 中间产物 + 更新规则）

本文件定义本技能的“阶段 → 输入 → 输出 → 必更新文档”的门禁模型，供脚本与日常执行统一使用。

## 0. 标准项目结构（本技能定义的“唯一结构”）

> SOP 仅用于启发；本技能以 `zhike-novel.config.json` 为唯一结构来源：没有配置则使用默认结构（见 `doc-spec.md`）。

## 1. 阶段门禁（进度传递）

> “门禁”只检查是否具备进入下一步的输入，不要求该步输出已经完成。
> 幂等入口建议：新会话开始先运行 `zn_validate.py --format json`，用其中的 `inferred_stage` + `next_target` 决定下一步做什么。
> 注意：门禁里对 `Setting.md`/`Timeline.md`/`map.md` 的校验不是“存在即通过”，而是要求“有实际内容而不是空模板”，以保证进度定位不跳步。

### background（背景设定）
- 输入（前置条件）
  - `项目介绍.md`（推荐；缺失不阻断，但会告警）
- 输出（主要产物）
  - `Setting.md`（世界观/时代/规则的最小可用设定）
  - `Timeline.md`（初步时间线）
  - `map.md`（势力/地点初步分布）
  - 词条目录建立（默认：`词条/`）
- 会话结束必更新
  - `项目状态记录.md`

### outline（大纲创作）
- 输入（前置条件）
  - `Setting.md`、`Timeline.md`、`map.md`
  - 已存在的相关词条（至少目录存在）
- 输出（主要产物）
  - `outline.md`（总纲/分卷结构）
- 会话结束必更新
  - `项目状态记录.md`、涉及到的词条（如新增势力/场景）

### chapter-outline（细纲创作）
- 输入（前置条件）
  - `Setting.md`
  - `outline.md`（推荐；缺失会告警）
  - `细纲/` 目录存在（默认：`细纲/`）
  - 已有分卷/上一章信息（若非首章：上一章正文存在）
- 输出（主要产物）
  - `细纲/第X章.md`（见 `doc-spec.md` 的结构要求）
  - 新要素清单（推动词条创建/更新）
- 会话结束必更新
  - `项目状态记录.md`、新要素对应词条（至少创建空壳并标注“待补”）

### drafting（正文创作）
- 输入（前置条件）
  - 存在对应 `细纲/第X章.md`
  - 相关词条齐全（至少文件存在；引用不应断链）
- 输出（主要产物）
  - `正文/第X章 章节标题.md`（默认：`正文/`）
- 会话结束必更新
  - `项目状态记录.md`、出场记录/关联信息（写进词条）

### qa（质量检查）
- 输入
  - 待检查的章节正文
  - 相关词条与设定文档
- 输出
  - 问题清单（优先级 + 建议）
  - 必要时回写：修正文/词条不一致点（先确认冲突再改）

## 2. 文档更新规则（必须遵守）

### 2.1 最小化原则
- 词条只写“正文里已出现/已确认会用”的信息；不要提前写未来剧情的硬设定。
- 设定文档只补“当前剧情必需”的规则；避免一次性把世界全写死。

### 2.2 引用规范（强制）
- 统一引用格式：`【详见：[文件名.md]】`
- 引用必须可解析到真实文件（脚本会检查断链）。

### 2.3 冲突处理（强制）
- 发现冲突：先报告“冲突点 + 影响范围 + 修复方案”，等待用户确认后再改。

### 2.4 进度记录（强制）
- 每次会话结束前：在 `项目状态记录.md` 的“最近更新”追加一条记录，并同步“任务状态”。
