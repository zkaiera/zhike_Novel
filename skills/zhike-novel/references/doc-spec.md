# 文档规范与校验点（供脚本与执行统一）

本文件对应 `scripts/zn_validate.py` 的校验逻辑：尽量只做“可自动验证”的硬规范（命名/标题结构/引用断链/进度文档），而不尝试用脚本判断文学质量或过度设定。

## 1. 根目录基础文档（建议始终存在）

- `项目介绍.md`：项目定位与创作要求（背景设定SOP前置输入）
- `Setting.md`：背景设定（最小可用，动态完善）
- `Timeline.md`：时间线（关键节点优先）
- `outline.md`：总纲/分卷/主支线/伏笔（大纲阶段产物）
- `map.md`：地图/地点/势力分布（最小可用）
- `项目状态记录.md`：进度追踪（会话结束前强制更新一次）

## 2. 目录布局与命名（标准结构 + 可配置）

本技能采用“单一标准结构”，并允许通过 `zhike-novel.config.json` 修改目录名/文件名，以适配你未来的偏好。

### 2.1 默认标准结构
- `词条/`：重要词条目录（entries）
- `细纲/`：细纲目录（chapter outlines）
- `正文/`：正文目录（chapters）

### 2.2 配置文件：zhike-novel.config.json（可选，但推荐）
如果存在该文件，脚本会以它为准。推荐结构示例：

```json
{
  "version": 1,
  "files": {
    "project_intro": "项目介绍.md",
    "setting": "Setting.md",
    "timeline": "Timeline.md",
    "outline": "outline.md",
    "map": "map.md",
    "status": "项目状态记录.md"
  },
  "dirs": {
    "entries": "词条",
    "chapter_outlines": "细纲",
    "chapters": "正文"
  }
}
```

## 3. 词条文件（默认：词条/；以配置为准）

### 3.1 文件名（强制）
- `角色-xx.md`
- `场景-xx.md`
- `势力-xx.md`
- `其他-xx.md`

### 3.2 内容结构（强制）
词条必须包含以下标题（顺序可灵活，但必须存在）：
- `## 基本信息`
- `## 关联信息`
- `## 出场记录`

建议首个非空行以 `# ` 开头作为词条标题。

## 4. 细纲文件（默认：细纲/第X章.md；以配置为准）

### 4.1 文件名（强制）
- `第1章.md`、`第2章.md` ...（只校验“第<数字>章.md”这一类）

### 4.2 内容结构（强制）
细纲文件需至少包含以下标题：
- `## 爽点设计`
- `## 剧情承接`
- `## 出场要素`
- `## 剧情大纲`
- `## 转场设计`
- `## 新要素标记`

建议首个非空行形如：`# 第XX章 章节标题`

## 5. 正文文件（默认：正文/第X章 章节标题.md；以配置为准）

### 5.1 文件名（建议）
- `第1章 异常数据.md`（脚本对不符合命名的文件给出警告而非错误）

### 5.2 细纲对应关系（建议）
如果存在 `细纲/第X章.md`，建议对应章正文也存在；否则脚本会提示“可能缺少细纲”。

## 6. 交叉引用（强制）

### 6.1 统一引用格式
- `【详见：[文件名.md]】`

### 6.2 引用可解析
引用必须能解析到真实文件（脚本会扫描全项目 `.md` 并检查断链）。

## 7. 进度传递（强制）

- `项目状态记录.md` 建议包含：
  - `# 项目状态记录`
  - `## 当前阶段`
  - `## 任务状态`
  - `## 最近更新`
  - `## 注意事项`
- 脚本会对“进度文档修改时间明显落后于其他文档”发出警告（意味着你可能忘了会话结束前同步进度）。

### 7.1 阶段字段（建议）
`- 所处阶段：` 建议填写为单值（例如：`未开始`、`背景设定`、`大纲创作`、`细纲创作`、`正文创作`、`质量检查`），避免用“选项列表”占位符导致 Agent 无法幂等判断。
